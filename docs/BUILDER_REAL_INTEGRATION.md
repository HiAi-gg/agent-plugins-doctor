# Real Builder Integration Results

This document records the results of testing Doctor against real Builder
output. Doctor's simulated Builder fixtures
(`tests/fixtures/builder-generated/from-*`) were replaced with plugins
generated by the actual Agent Plugin Builder binary, so the compatibility
claim is verified end-to-end instead of assumed.

## Builder Version

- Repository: https://github.com/HiAi-gg/agent-plugin-builder
- Version: 0.0.6
- Commit: `7a0b9bd84d86d9d250bf0f9a399256c831c8f79e`
- Date: 2026-08-07 20:50:21 +0100

## How the fixtures were generated

The Builder repository was cloned to `/tmp/agent-plugin-builder`, built with
`bun install && bun run build`, and each generator command was run into a
scratch directory. The generated directories were copied byte-for-byte into
`tests/fixtures/builder-generated/real-builder/`. No file was edited after
generation.

| Fixture           | Builder command                                                                                           |
| ----------------- | --------------------------------------------------------------------------------------------------------- |
| `init/`           | `agent-plugin init --name test --description test --yes`                                                  |
| `create-skills/`  | `agent-plugin create --name test-skills --skills-only`                                                    |
| `create-mcp/`     | `agent-plugin create --name test-mcp --mcp-only --mcp-type stdio --mcp-command node --mcp-args server.js` |
| `migrate-claude/` | `agent-plugin migrate <claude-project> --from claude`                                                     |
| `migrate-cursor/` | `agent-plugin migrate <cursor-project> --from cursor`                                                     |

Notes:

- Builder's `init` command has **no `--stdin` flag** (the original test plan
  assumed one). Non-interactive init is done with `--name`, `--description`,
  and `--yes`; the `--yes` flag skips all prompts. The initial sketch
  `echo '{"name":...}' | agent-plugin init --yes --stdin` therefore does not
  apply to Builder 0.0.6 and was adapted.
- The migration sources were minimal but realistic: a Claude project with a
  `CLAUDE.md` plus a `.claude/skills/greeter/SKILL.md`, and a Cursor project
  with a `.cursor/skills/helper/SKILL.md`. Both migrations succeeded with
  exit 0.

## Classifications

### PASS

All five Builder-generated plugins (init, create-skills, create-mcp,
migrate-claude, migrate-cursor) pass Doctor validation with exit 0 and no
diagnostics. Builder's output is byte-valid against the Agent Plugins 1.0.0
spec as enforced by Doctor's vendored schemas and 29 rules.

### FAIL-DOCTOR

None. Doctor did not reject any valid Builder output.

### FAIL-BUILDER

None. No Builder-generated plugin was invalid per the spec.

### FAIL-SPEC

None.

### FAIL-CONTRACT

None. Interesting observations, none blocking:

- `create` emits a manifest containing only `$schema` and `name` — no
  `description` — while `init` fills in `description`, `version`, and
  `license`. The schema permits both shapes (only `$schema` and `name` are
  required), so this is not a spec violation, but the two commands are
  inconsistent. Builders may want to standardize on one manifest shape.
- `migrate` names every migrated plugin `migrated-plugin` unless the source
  declares otherwise. Acceptable for a first migration; worth noting for
  users generating multiple plugins.

### UNCLEAR

None.

## Conclusion

Doctor correctly validates all real Builder outputs. No bugs found in either
tool. The fixtures and the integration test
(`tests/integration/builder-real.test.ts`) pin this compatibility: any future
Doctor or Builder change that breaks it fails CI. The simulated
`from-*` fixtures remain as the Builder integration contract tests
(`tests/integration/builder-contract.test.ts`); the real-builder fixtures
prove the contract holds against actual generated output.

## Reproducing

```bash
# Clone and build Builder
cd /tmp
git clone https://github.com/HiAi-gg/agent-plugin-builder.git
cd agent-plugin-builder && bun install && bun run build

# Generate plugins (see table above; init has no --stdin flag)
mkdir -p /tmp/builder-outputs
# ... run each Builder command into /tmp/builder-outputs ...

# Run Doctor against each output
./packages/cli/bin/agent-plugin-doctor check /tmp/builder-outputs/<fixture>
```

All five commands exit `0` with `Result: No issues found`.
